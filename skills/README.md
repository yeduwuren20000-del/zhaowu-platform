# AI 技能（skills）

「让 AI 一键配置」的说明书就放在这里。技能不是插件也不是代码，它是一份结构化文档：AI 读到它，就知道该调哪个接口、按什么顺序、哪些事绝对不能做。

## 装着什么

| 目录 | 作用 |
| --- | --- |
| `zhaowu-server-import/` | 把一段连接信息（ssh 命令 / `.ssh/config` 片段 / 云控制台字段块）变成一条**能探活**的服务器记录 |

每个技能目录固定两个文件：`SKILL.md`（给 AI 读的正文）和 `references/`（展开的接口细节）。

## 装到 WorkBuddy

复制目录即可，不需要重启：

```bash
cp -r skills/zhaowu-server-import ~/.workbuddy/skills/
```

Windows PowerShell：

```powershell
Copy-Item -Recurse skills\zhaowu-server-import "$env:USERPROFILE\.workbuddy\skills\"
```

装好后在对话里直接说「帮我加个服务器」，粘上 ssh 命令就行——AI 会自己走「解析 → 补全 → 建档 → 双层探活」。

## 不给 AI 装技能也能用

工作台「新增服务器」对话框里有「让 AI 帮我配」按钮，点一下把同一套指令复制到剪贴板（已经填进去的连接信息会一并带上）。那段指令是**自包含**的：端点、三步流程、红线全写在里面，粘给任何 AI 都能跑。

技能的价值只是省掉这句话——AI 不用等你开口就知道该做什么。

## 三条红线

技能里写死的规矩，不是建议：

1. **不保存密码、passphrase、私钥正文**。后端会直接 400 拒收这些字段，只接受 `keyPath`（私钥路径）和 `passwordEnv` / `passphraseEnv`（环境变量名）。
2. **不猜**。解析不出来就问用户，不编造 host / 用户名 / 端口。少填可以，填错不行。
3. **只填空字段**。用户手工填过的值不覆盖，提交前把"识别到什么、补了什么、还缺什么"摊开给用户看。

## 为什么要写成技能而不是提示词文档

同一套规则如果只存在某个对话框里，换台机器、换个 AI 客户端就丢了。放进仓库后它能跟着代码走版本，`git log` 能查到规则是哪次改的、为什么改。
